## 대표 활동 Hugo 포트폴리오 제작과 배포

- **활동 기간:** 2026년 10월 15일부터 진행 중
- **활동 형태:** 개인 수업 과제
- **현재 상태:** 공개 배포 완료, 콘텐츠와 검증 기록 보완 중

### 활동 목적

초급프로젝트 과제에서 자기소개와 실제 학습 과정을 보여주는 개인 사이트를 만들고, GitHub에 변경을 올리면 공개 사이트에 자동으로 반영되는 배포 흐름을 구성하는 것이 목표입니다. 사이트가 열리는 것뿐 아니라 메뉴 이동과 작은 화면에서의 사용도 확인하고 있습니다.

### 본인 역할과 AI 지원 범위

개인 과제로 Hugo Coder 테마를 다운로드하고 제공된 준비 스크립트에 MyProfile 저장소 주소를 입력했습니다. Git Bash에서 초기 업로드와 이름·소개·GitHub 링크 변경을 커밋하고 push했습니다. 이후 소개 내용과 대표 활동 방향을 정하고 AI에 문안·설정·코드 보완을 요청했습니다.

대표 활동은 진행 중인 캡스톤 대신 이 포트폴리오 제작·배포로 정했습니다. 캡스톤은 아직 진행 초기라 개인 구현·검증 결과가 없어서, 완료 성과처럼 쓰기보다 실제로 수행하고 확인할 수 있는 활동을 대표로 삼았습니다. 작업 중에는 화면 아래쪽에 크게 떠 있던 화면 모드 버튼을 받아들이지 않고 제거를 요청했고, 대신 설정 메뉴 안에서 고르도록 제안했습니다. 배포가 막혔을 때는 Actions에서 직접 재실행과 수동 실행을 했습니다.

한국어 콘텐츠 정리, 모바일 메뉴와 접근성 코드, 경로 수정, README 작성 및 일부 커밋·배포 확인에는 Codex(10월 15~16일)의 도움을, 예시 콘텐츠 정리·푸터 개선·배포 실패 기록·검증 기록에는 Claude Code(10월 16일)의 도움을 받았습니다. 초기 직접 수행한 작업과 AI가 도구로 수행한 수정·검사는 구분합니다. AI 검사 결과를 본인의 직접 검사 결과로 표시하지 않습니다.

### 사용 기술과 실제 적용

- **Hugo와 Markdown:** 소개·프로젝트·학습 기록을 페이지로 만들고 정적 HTML을 생성했습니다.
- **Git과 GitHub:** 실제 수정 내용을 커밋으로 남기고 main 브랜치에 push했습니다.
- **GitHub Actions와 Pages:** main push를 받아 빌드한 사이트를 공개 HTTPS 주소에 배포했습니다.
- **HTML과 CSS:** AI 지원으로 메뉴·본문 링크 표시·키보드 초점·배포 경로를 수정했습니다. 화면 모드 전환 버튼은 사용 후 불편하여 제거했습니다. 코드와 결과를 읽고 검증하는 학습을 이어가고 있습니다.

### 수행 과정과 방법의 선택 이유

1. Hugo Coder 테마와 수업 제공 스크립트로 초기 사이트를 준비했습니다. 테마 선택 당시의 자세한 개인 판단은 별도로 기록하지 않았습니다. 현재는 텍스트 중심의 소개와 학습 기록을 구성할 수 있어 이 구조를 유지하고 있습니다.
2. Git Bash에서 업로드한 뒤 Actions와 공개 주소를 확인했습니다. 준비 스크립트 실행과 원격 업로드는 서로 다른 단계였습니다.
3. 예시 인물·메뉴를 본인 정보와 한국어 콘텐츠로 바꾸었습니다.
4. 모바일 메뉴는 작은 화면에서도 메뉴 항목을 바로 찾고 키보드로 접근하도록 접지 않고 항상 보이는 방식으로 보완했습니다. 이는 AI가 제안·구현한 개선이며 실제 동작 검사 범위를 함께 기록했습니다.
5. 글꼴·아이콘 경로와 불필요한 파일 참조를 수정한 후 빌드와 공개 배포를 다시 확인했습니다.
6. 화면 모드 버튼은 화면을 가려 제거하고, 상단 **설정** 메뉴(소개·프로젝트·학습 기록에 이은 네 번째 메뉴) 안에서 밝게·어둡게·기기 설정을 고르도록 바꾸었습니다. 아이콘과 문구가 거슬린다는 사용 경험에 따라, 늘 떠 있는 버튼 대신 필요할 때 찾아 쓰는 메뉴 방식을 택했습니다.
7. 배포 단계가 실패했을 때 Actions 로그의 오류 문장으로 원인을 좁히고, 재실행·수동 실행 뒤 다음 push의 자동 배포까지 확인했습니다. 자세한 과정은 [배포 실패와 복구 기록](../posts/deploy-failure-recovery/)에 있습니다.
8. 테마 예시 글과 빈 분류 페이지를 정리하고, 공개 화면 아래쪽에 맨 위로 링크와 실제 배포된 커밋(배포 버전)을 표시해 보고서의 버전과 공개 화면을 대조할 수 있게 했습니다.

### 배운 점과 다음 개선

준비 스크립트가 Git 업로드까지 대신하지 않으며, push 뒤에도 Actions와 실제 화면을 확인해야 한다는 점을 배웠습니다. git diff로 수정 내용을 비교하고 보기 화면에서 q로 나오는 방법도 익혔습니다.

직접 확인한 결과는 다음과 같습니다.

- Chrome 200% 확대에서 메뉴와 글을 읽고 사용할 수 있었습니다. 화면 모드 아이콘과 문구가 거슬린다는 의견을 전달해 AI 지원으로 버튼을 제거했습니다.
- Edge에서 마우스 없이 Tab으로 소개·프로젝트·학습 기록 메뉴를 선택하고 Enter로 이동했을 때 선택 테두리가 보였고 세 메뉴 모두 열렸습니다.
- 화면 모드를 다시 고를 수 있도록 상단 **설정** 메뉴 안으로 옮기자고 제안했고, 어둡게 선택 후 다른 페이지 이동·새로고침에도 유지되고 밝게로 되돌아오는 것을 확인했습니다.

현재 한계는 AI가 수행한 검사 중 본인이 직접 재현하지 않은 항목(다른 브라우저, 캐시를 끈 접속 등)이 남아 있다는 점입니다. 다음에는 이 항목을 직접 확인하고, 유효 커밋 집계와 보고서를 실제 변경에 맞춰 보완하겠습니다.
